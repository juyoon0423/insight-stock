# 발표(라이브 데모) 리허설 체크리스트

발표일 2026-11-14. 평소에는 인스턴스를 꺼두므로 발표 전에 켜고 확인할 것들을 순서대로 적었다.
각 항목의 근거는 괄호 안의 문서에 있다. **모든 명령의 상세는 [deploy.md](./deploy.md)** — 여기는
"무엇을 어떤 순서로 확인하는가"만 적는다.

마지막 실제 점검: 2026-10-12 (백엔드 `7500c5e` 재배포, Nginx 레이트 리밋, 프론트 재배포 후 검증).
그 뒤에 코드가 더 바뀌었으면(이 문서 맨 아래 "배포되지 않은 변경") 재배포부터 해야 한다.

## 1. 며칠 전 (D-3 ~ D-1)

- [ ] **인스턴스를 t3.medium으로 올려서 켠다** (deploy.md 19절). t3.small로는 백엔드를 띄우지
      않는다 — 첫 검색 직후 인스턴스가 무응답이 된다.
- [ ] **SSH가 되는지 확인한다.** 보안 그룹의 22번 규칙은 "내 IP"로 고정돼 있다. 발표장 네트워크
      에서 접속하려면 그 IP로 규칙을 갱신해야 한다(deploy.md 1절). 발표장에서 SSH를 쓸 계획이
      없다면 집에서 전부 띄워두고 간다.
- [ ] **Postgres와 Elasticsearch가 둘 다 `healthy`인지 확인한 뒤에** 백엔드 jar를 띄운다
      (`SERVER_PORT=8082`, deploy.md 7절). ES가 준비되기 전에 띄우면 기동에 실패하고 502만 나온다.
- [ ] **인증서 만료일을 확인한다** (`sudo certbot certificates`). 2026-10-12 기준 만료는
      2027-01-10이라 발표일에는 문제없지만, 자동 갱신은 인스턴스가 꺼져 있는 동안 돌지 않는다.
- [ ] **헬스체크**: `curl https://insightstock.site/actuator/health` → `{"status":"UP"}`.
- [ ] **코드가 바뀌었으면 재배포한다.** 백엔드를 먼저(deploy.md 18절), 프론트를 나중에
      (`cd frontend && npx vercel --prod`). **Vercel은 push만으로 배포되지 않는다.**
- [ ] **데모 질의를 실제 화면에서 전부 한 번씩 눌러본다** (아래 2절). 화면의 예시 질문 칩 3개도
      포함 — 칩 질문은 2026-10-12 점검에서 확인하지 않았다.
- [ ] **알림을 시연할지 정한다.** 시연한다면 `notification.collector.enabled`가 켜져 있어야 하고,
      관심 등록 **이후에 수집된** 공시가 있어야 배지가 생긴다(수집은 10분 간격). 당일에 만들기는
      어려우므로 미리 계정에 알림이 쌓인 상태를 만들어 둔다. EC2에서 이 설정이 현재 켜져 있는지는
      확인되지 않았다.
- [ ] **청중이 직접 써보게 할지 정한다.** 레이트 리밋이 IP 단위라, 같은 Wi-Fi의 청중은 합쳐서
      `/answers` 분당 20회로 계산된다. 여럿이 동시에 써보게 하려면 Nginx의 `rate`/`burst`를
      올리고 reload한다(deploy.md 20절).

## 2. 데모 질의

**검색 데이터는 2026-07 말에 멈춰 있다**(청킹/임베딩 스케줄러가 꺼져 있음). "최근", "이번 달"
같은 질문에는 답하지 못한다. 2026-07 하순에 접수된 공시에 대한 질문만 쓴다.

질문은 측정에 쓴 문장 **그대로** 입력한다. 뒤에 다른 문장을 덧붙이면 검색 결과가 달라져 같은
질문이 거절될 수 있다(2026-10-12 배포 환경에서 관찰 — progress.md).

### 잘 되는 질의 (보여줄 것)

| 질의 | 기대 답변 | 확인한 곳 |
|---|---|---|
| 신한지주가 소각하기로 한 보통주식 수와 소각예정금액은? | 6,698,565주 / 700,000,000,000원 | 배포 환경 |
| 코아스가 정정공시한 전환사채의 전환가액과 정정 후 만기일은? | 2,132원 / 2029년 10월 23일 (출처 2건) | 배포 환경 + 브라우저 |
| 더블유게임즈의 2025년 연간 매출액은 얼마인가? | 719,897백만원 | 배포 환경 |
| 동아쏘시오홀딩스가 동아제약을 합병하는 목적은 무엇인가? | 서술형 답변(경쟁력 내재화, 지배구조 단순화 등) | 로컬 측정 |
| 두산의 1주당 배당금과 배당금총액은 얼마인가? | 1,000원 / 17,882,307,000원 | 로컬 측정 |

"로컬 측정"은 [answer-quality-eval.md](./answer-quality-eval.md)의 결과다. 배포 환경의 데이터는
로컬과 같지만(deploy.md 19절) 답변은 매번 조금씩 다를 수 있으니 직접 눌러 확인한다.

### 환각을 제어하는 것을 보여주는 질의

| 질의 | 기대 동작 |
|---|---|
| 테슬라의 최근 자율주행 기술 개발 현황은 어떤가요? | "찾지 못했습니다" + "관련 공시를 찾지 못했습니다" 안내 |
| 가나다라마전자가 결정한 유상증자 규모는 얼마인가요? | 같은 거절 — 다른 회사의 유상증자 공시를 가져다 답하지 않는다 |

### 한계 사례 (피하거나, 한계로 설명할 것)

| 질의 | 결과 | 원인 |
|---|---|---|
| 현대모비스의 1주당 배당금은 얼마인가? | 거절 (정답은 1,500원) | 정답 공시가 검색 top-50에도 없음 |
| 롯데칠성음료의 실적발표회는 언제, 어떤 방식으로 열리는가? | 거절 | 정답 공시가 검색 15위 (컨텍스트는 10위까지) |
| 기도산업이 최근 은행 등에서 빌린 돈의 규모는 어떻게 변화했나요? | 거절 | 같은 공시의 다른 청크만 검색됨(925개 청크 문서) |

"틀린 답을 하지는 않지만 못 찾는 질문이 있고, 원인은 LLM이 아니라 검색이다"를 설명하는 재료로
쓸 수 있다 — 측정 결과는 answer-quality-eval.md 5절. `/search` 화면에서 같은 질의를 넣으면
키워드/벡터 순위가 어떻게 갈렸는지 보여줄 수 있다.

## 4. 문제가 생겼을 때

| 증상 | 먼저 볼 것 |
|---|---|
| 화면에 "서버에 연결할 수 없습니다" | 헬스체크. 502면 백엔드 프로세스가 죽은 것 — `ps`로 확인 후 재기동(deploy.md 7절) |
| 모든 요청이 타임아웃, SSH도 안 됨 | 메모리 부족으로 인스턴스가 멈춘 것(t3.small로 켰을 때의 증상). 강제 정지 후 t3.medium으로 재기동(deploy.md 17절, 19절) |
| "요청이 너무 많습니다" (429 `RATE_LIMITED`) | Nginx 레이트 리밋. 몇 초 기다리면 풀린다. 계속 걸리면 `rate`/`burst`를 올리고 reload |
| "지금 요청이 몰려…" (429 `LLM_RATE_LIMITED` / `SEARCH_RATE_LIMITED`) | OpenAI 분당 토큰 한도. 1분 기다린다 |
| "답변 생성 중 일시적인 오류" (502 `LLM_UNAVAILABLE`) | OpenAI 장애 또는 크레딧 소진. `app.log`에서 원인 확인. 검색 화면(`/search`)은 LLM 없이 동작하므로 그쪽으로 시연을 이어간다 |
| 잘 되던 질문이 거절됨 | 질문 문장을 측정 때와 똑같이 입력했는지 확인. 다른 "잘 되는 질의"로 넘어간다 |

원인을 볼 때는 `grep ANSWER_LOG ~/insight-stock/app.log | tail`로 마지막 요청들이 무엇을 검색하고
어떻게 답했는지 바로 볼 수 있다(검색 시간/LLM 시간, 거절 여부 포함).

**최후의 대안**: 로컬에서 `docker compose up -d` → `./gradlew bootRun` → `npm run dev`로 같은
데이터(로컬 DB)를 띄워 시연한다. 발표 전날 로컬에서도 한 번 띄워 확인해 둔다. 이때 OpenAI 호출은
그대로 발생한다.

## 배포되지 않은 변경 (2026-10-12 기준)

마지막 배포(`7500c5e`) 이후 main에 들어간 백엔드 변경 — 다음에 인스턴스를 켤 때 재배포할 것:

- LLM 응답 방어(`max_tokens` 1000, 본문 없는 응답과 콘텐츠 필터를 502로 처리)
- 검색 인덱스에만 있고 DB에 없는 청크를 결과에서 제외
- DART 호출 타임아웃(connect 5초 / read 60초), 스케줄러 스레드 4개
- 질의 임베딩의 429 재시도 값 분리(2회, 500ms 시작)
- 프롬프트 보강(2026-10-13): 컨텍스트에 접수일자, `<context>`/`<question>` 태그 경계와 규칙 6·7
  (answer-quality-eval.md 10절)

프론트는 변경 없음(테스트만 추가).
